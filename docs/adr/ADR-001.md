# ADR-001: Using an AI assistant to implement the Lab 5 TODOs

**Date:** 2026-11-12  **Author:** <your name>  **Milestone:** Lab 5
**Tool and model used:** Claude Code (Claude Opus 5.5)

## Context
Lab 5 asks for the TODOs in the Study Notes app: the `Note` model, `AuthRepository`,
`NotesRepository`, `NotesScreen`, `MessagingService`, Firestore security rules and own tests.
I wanted help writing the code quickly, but every line has to match the provided tests in
`test/lab05_test.dart` and I have to be able to explain it. No keys, passwords or
`lib/firebase_options.dart` were given to the assistant.

## Prompt
```
Complete the TODOs in lib/ (Parts 1-6) and firestore.rules following the lab sheet,
then write at least 2 meaningful own tests in test/own_test.dart.
The provided tests in test/lab05_test.dart must not be changed.
```

## Result
- `Note.fromFirestore` checks `title is! String || body is! String` → `FormatException`;
  `createdAt` is `Timestamp?.toDate()` or null. `toFirestore()` uses `FieldValue.serverTimestamp()`.
- `AuthRepository.messageFor` is a switch expression; `signIn`/`signUp` trim the email and wrap
  `FirebaseAuthException` in `AuthFailure`.
- `NotesRepository.watchNotes` = `orderBy('createdAt', descending: true).snapshots().map(...)`;
  `addNote` trims and validates the title (1–100), then `add(note.toFirestore())`.
- `NotesScreen`: AppBar + sign-out, FAB → `AddNoteDialog`, `StreamBuilder` with error /
  spinner / empty / `Dismissible` list.
- `firestore.rules`: owner-only access on `users/{uid}/notes/{noteId}`; create/update also
  require a string title of 1–100 characters.
- `MessagingService`: permission → token → topic `comp205`; `onMessage` → `show(title, body)`.

## Rejected suggestion(s)
1. **Deleting only through the stream in `NotesScreen`.** The simplest version calls
   `deleteNote` in `onDismissed` and waits for Firestore to remove the item. Flutter requires a
   dismissed `Dismissible` to leave the tree immediately, otherwise it throws
   "A dismissed Dismissible widget is still part of the tree". I kept a local `_dismissed` set that
   hides the note at once.
2. **Rules with `allow read, write: if request.auth != null;`** — this lets any signed-in
   user read everybody's notes. Rejected for security; the rule must compare
   `request.auth.uid == uid` (and is checked in the Rules Playground: another uid → Denied).
3. **Using `createdAt: DateTime.now()` on the client** — rejected: the client clock can be
   wrong, the lab requires `FieldValue.serverTimestamp()`.

## Verification
- `flutter test`: all 15 provided tests and my own tests in `test/own_test.dart` pass.
- `flutter analyze`: no issues.
- Manual: sign-up / sign-in on the emulator, add and swipe-delete notes, Rules Playground
  (other uid → Denied, own uid → Allowed), FCM test message (SnackBar in foreground,
  tray notification in background), green GitHub Actions run.

## What I learned
Security belongs in the Firestore rules, not only in the app: the app checks the title for a
nice error message, but the rules are what actually stop other users. Fakes
(`FakeFirebaseFirestore`, `MockFirebaseAuth`) let me test Firebase code without a project.
